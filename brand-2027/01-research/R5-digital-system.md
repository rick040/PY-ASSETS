## R5 Digital system

### Key findings

- **DTCG is stable.** The Design Tokens Community Group published its first stable version, 2025.10, on 28 October 2025: a Format, a Color and a Resolver module ([W3C CG](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/)). It is a Community Group report, not a W3C Standard; the Resolver module handles modes such as light and dark ([Resolver](https://www.designtokens.org/tr/2025.10/resolver/)). Keys: `$value`, `$type`, `$description`, `$extensions` (reverse-domain keys; tools must preserve unknown data), `$deprecated`. Aliases are `{group.token}` or JSON Pointer `$ref`. Composite types: `border`, `shadow`, `gradient` (stops with `position` 0 to 1), `typography`, `transition`, `strokeStyle`. Dimensions and durations are `{value, unit}` objects ([Format](https://www.designtokens.org/tr/2025.10/format/)).
- **Colour is an object, not a hex string.** In 2025.10, `$value` = `{colorSpace, components, alpha?, hex?}`. The spec supports 14 spaces, including `srgb`, `oklch` and `display-p3`, and `hex` is only an optional fallback ([Color](https://www.designtokens.org/tr/2025.10/color/)). The gradient type has no angle, so the "verloop" direction must live in `$extensions` or in code (assumption, inferred from the spec).
- **Tool support is real but partial.** Style Dictionary: DTCG since v4, 2025.10 "work in progress in v5" ([SD](https://styledictionary.com/info/dtcg/)). Terrazzo claims full DTCG, resolver in 2.0 ([Terrazzo](https://terrazzo.app/docs/)). Tokens Studio: DTCG since plugin 2.0.0 ([release](https://github.com/tokens-studio/figma-plugin/releases/tag/2.0.0)). Figma announced native DTCG variable import/export (one JSON per mode); rollout date is unclear in secondary sources and export reportedly drops descriptions ([Obra](https://figma.obra.studio/design-tokens-community-group-w3c-release/), [forum](https://forum.figma.com/ask-the-community-7/native-variable-export-feature-47831)).
- **Mature systems use three tiers.** NL Design System: Brand, Common, Component; names `prefix.block.element.modifier.property` (`voorbeeld.button.primary-action.background-color`); components read only component tokens; dark and high-contrast themes are supported ([NLDS](https://nldesignsystem.nl/handboek/design-tokens/)). Likewise Material ref/sys/comp ([material-web](https://github.com/material-components/material-web/blob/main/docs/theming/README.md)), Spectrum primitive/semantic/component ([Spectrum](https://spectrum.adobe.com/page/design-tokens/)). Atlassian names `color.background.brand.bold` and treats light, dark, high contrast and reduced motion as themes ([Atlassian](https://atlassian.design/foundations/tokens/design-tokens)).
- **WCAG 2.2 AA for booking.** The relevant criteria are 1.4.3 (4.5:1 text), 1.4.11 (3:1 UI), 2.4.11 Focus Not Obscured (AA; sticky footers and cookie bars), 2.5.8 Target Size (AA, 24×24 CSS px), 3.3.7 Redundant Entry (A; licence plate and email entered once) and 3.3.8 Accessible Authentication (AA; no transcription puzzles) ([W3C](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)). GOV.UK uses a yellow and black focus state that meets 1.4.11 on any background ([GOV.UK](https://design-system.service.gov.uk/get-started/focus-states/)). APCA was removed from the WCAG 3 drafts in July 2023, and WCAG 3's contrast method is still undecided ([Roselli](https://adrianroselli.com/2026/04/wcag3-contrast-as-of-april-2026.html)).
- **The EAA applies.** The ACM has enforced the accessibility rules since 28 June 2025. They cover "websites and apps where you can purchase, take out, or reserve" services, at businesses with more than 10 staff or more than €2M turnover ([ACM](https://www.acm.nl/en/publications/acm-calls-businesses-prepare-themselves-new-rules-regarding-accessibility-websites-and-apps)). EN 301 549 v4.1.1, published 2 September 2026, adopts WCAG 2.2 AA. It is pending citation in the Official Journal, expected around 30 November 2026 ([Deque](https://www.deque.com/blog/en-301-549-v4-1-1-is-final-what-changed-what-it-means-and-what-you-should-do/)).
- **Dark mode elevation is surface colour.** Atlassian makes higher surfaces lighter, keeping shadows on raised and overlay ([Atlassian](https://atlassian.design/foundations/elevation)). The navy brand fails on dark backgrounds (computed): #1A3580 on #121212 is 1.66:1 and on #0D142E is 1.61:1, while #32B9CD on #0D142E is 7.74:1.
- **Motion tokens.** Carbon separates productive motion from expressive motion. Its durations are 70, 110, 150, 240, 400 and 700 ms, and its standard productive easing is `cubic-bezier(0.2, 0, 0.38, 0.9)` ([Carbon](https://carbondesignsystem.com/elements/motion/overview/)). WCAG 2.3.3 (AAA) lets users disable motion triggered by interaction, with `prefers-reduced-motion` as technique C39 ([W3C](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)). Auto-playing motion over 5 s needs a pause control under 2.2.2, Level A ([W3C](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)).

### What this means for ParkingYou

- **Rebuild `tokens.json` in three DTCG tiers:** `color.blue.700` → `color.action.primary.bg` → `button.primary.bg`. Source in `.tokens.json`, built with Style Dictionary or Terrazzo into the Next.js/Payload CSS variables, so the website palette is aliased or retired (assumption). Adopt NLDS naming with a `py` prefix.
- **Carry print and signage data in `$extensions`.** This is a proposal: I found no shipped example, only vendor pitches ([pantonetools](https://pantonetools.com/tools/design-token-generator)). A custom Style Dictionary format can write `.ase` swatches with `adobe-ase` (MIT, writes CMYK and spot swatches; [npm](https://registry.npmjs.org/adobe-ase)) and a signage spec sheet (CSV or PDF). This addresses the 15 blues in print.

```json
"blue": { "700": { "$type": "color",
  "$value": { "colorSpace": "srgb", "components": [0.102, 0.208, 0.502], "hex": "#1a3580" },
  "$extensions": { "nl.parkingyou.production": {
    "cmyk": [100, 83, 0, 17], "ral": "5002", "ralMatch": "nearest",
    "pantone": null, "vinyl": null } } } }
```

- **Plan four modes:** light, dark, high contrast, and "garage" (signage and in-garage screens: larger minimum sizes, only pairs at 7:1 or more) (assumption).
- **In dark mode, do not use navy as text or as a border.** Map `color.text.brand` to aqua or a light blue tint. Use deep navy #0D142E as the base surface (white text on it is 18.16:1, computed) and lighter navy steps for elevation.
- **Motion:** a few tokens (`duration.fast`, `moderate`, `slow`, `easing.standard`, `enter`, `exit`). The animated beeldmerk (pin drop, ring draw, aqua dot pop) is "expressive" and limited to splash and reels, under 1 s. A static frame replaces it under reduced motion (assumption).

### Open questions

- Is the website palette retired or aliased? The colour workstream needs to answer this before the semantic tier exists.
- Can Payload read the generated CSS directly, or does the CMS need its own token import?
- Who maintains the Pantone and vinyl codes (Oracal or 3M series), All Jobs or ParkingYou?
- Does the Aeroparker booking flow meet WCAG 2.2 AA, and who is liable under the EAA?
- Does the lightbox film colour need a separate "transmissive" value per token?
